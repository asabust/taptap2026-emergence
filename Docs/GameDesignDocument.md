## 2. 核心玩法

### 2.1 玩法定位与操作

参考康威生命游戏的邻域与死亡规则、移除繁殖机制的回合制 2D 解谜游戏。关卡是有限面积的二维方形网格，初始布置一定数量的细胞。玩家操纵一个特别的细胞作为可玩角色，每关恰好一个玩家细胞。

| 操作 | 已明确的行为 | 尚待明确 |
| --- | --- | --- |
| 四向移动 | 每次方向键按下移动一格，长按不连续移动；不能进入或穿过存活细胞所在格；不记录移动步数 | 阶段 5 实现采用上 → 右 → 下 → 左，单帧只处理一个操作 |
| 迭代 | 空格推进一轮生命细胞演化；玩家参与邻居计算但不会死亡；只记录迭代轮数 | 规则变体 |
| 重置 | R 恢复关卡初始布局与玩家初始位置，迭代轮数归零 | 无 |
| 后退 | Z 可撤销多轮迭代，同时恢复该次迭代前的玩家位置，丢弃此后的移动 | 快照实现与容量见第 2.5 节 |

移动与迭代是两种独立操作，不默认每次移动都会触发迭代。未触发迭代时，生命细胞状态不因时间流逝自动变化。

移动用于摆放特别细胞的位置，允许玩家来回行走与思考，不消耗迭代轮数。初始轮数为 0，每次成功完成迭代加 1；撤销恢复相应轮数，重置归零。建议空格、R、Z 同样只响应一次按下，长按不重复触发。

核心循环：**观察布局 → 移动角色、选择站位 → 按需创建或回收分身 → 主动触发迭代 → 观察布局与通路变化 → 继续干预 → 达成关卡目标**。撤销用于尝试与修正操作。

目前有同时存活分身数量上限；没有倒计时、敌人或额外空间限制系统。已有的有限网格、墙与存活细胞决定通行情况，不额外引入新限制。玩法是否形成有意义的选择，需通过具体关卡验证。

### 2.2 基础迭代规则

用户提供的规则图按中心格周围八格计算存活邻居数；角色移动为四方向，细胞演化的邻域为八方向，二者不同。

| 当前普通细胞状态 | 存活邻居数 | 下一轮状态 |
| --- | --- | --- |
| 死亡／空格 | 任意数量 | 保持死亡／空格，不生成新细胞 |
| 存活 | 少于 2 | 死亡（孤独） |
| 存活 | 2 或 3 | 保持存活 |
| 存活 | 大于 3 | 死亡（拥挤） |

一步迭代应基于同一份上一轮状态计算，再同时应用所有格子的结果。本轮死亡的细胞不影响同一步中其他格子的计算。关卡可独立启用孤独死亡与拥挤死亡，详见第 5.2 节。

已明确：地形细胞不演化、不贡献存活邻居数，迭代中的普通生命细胞只会存活或死亡，不会自动在空格诞生；主动分身是独立的创建操作。场景边界不循环连接（已确认），网格外与无效区域不能诞生细胞且不贡献存活邻居数。

### 2.3 地形、生命细胞与玩家细胞

| 类型 | 是否演化 | 是否贡献存活邻居数 | 占位规则 |
| --- | --- | --- | --- |
| 地形细胞 | 否 | 否 | 构成固定地形；生命细胞不能取代它 |
| 生命细胞 | 是 | 是 | 按关卡规则存续或死亡 |
| 玩家细胞 | 不因死亡规则消失 | 是 | 玩家操纵；生命细胞不能取代它 |

玩家细胞在每次迭代开始时，按当前位置作为一个存活邻居参与其他格子的计算；自身即使满足孤独或拥挤死亡条件也保留。玩家移开后，原位置留下空格（死亡状态），不留下普通生命细胞；后续迭代也不会自动在该空格生成生命细胞，但玩家可在满足分身条件时主动放置分身。

因此玩家站位能够改变附近生命细胞的演化，这是已有规则直接支持的玩法交互。

纸面例子：某普通生命细胞只有一个存活邻居。玩家移到它的另一个相邻格，使其邻居数变为两个，在开启孤独死亡时可保护它存活。相反，某细胞已有三个存活邻居，玩家移至相邻格使邻居数变为四个，在开启拥挤死亡时可使其死亡。其他格子仍需同步结算。

移除繁殖后，在普通细胞没有额外移动或生成机制的前提下，单次迭代的存活位置是迭代前存活位置的子集，迭代只会保持或减少数量；玩家主动分身可以在迭代之外增加普通生命细胞。撤销与重置可恢复旧状态，不属于繁殖。

### 2.4 数量统计与目标检查（已确认）

- 通关条件中的「生命细胞数量」仅统计普通生命细胞，不包含玩家细胞。玩家参与邻居计算，与目标数量统计是两种不同用途。
- 移动、分身创建、回收、迭代等有效状态改变完成后，统一检查全部通关目标；加载、撤销与重置后也按当前状态重新检查。编辑器对初始即满足目标的关卡显示提示。
- 通关目标只有角色位置、普通生命细胞位置、普通生命细胞数量三类。迭代轮数是独立上限，不是通关目标；不要求恰好第 x 轮才检查或通关。
- 多个实际目标仅支持全部满足，要求同一结算状态成立，不保留历史达成标记。轮数上限始终独立于目标组合。

三类通关目标见第 5.4 节；迭代上限的失败边界已确定，见第 5.4 节；关卡内容仍需原型验证。不预设成长或局外系统。

### 2.5 多轮撤销实现方案（建议）

使用迭代前状态快照栈，不通过反向运行生命游戏规则撤销。多种旧状态可能产生相同的新状态，因此不能从当前棋盘唯一还原上一轮。

每份快照保存：普通生命细胞的存活布局及分身来源标记、玩家坐标、迭代轮数，以及将来会影响规则的可变状态。分身已用名额从快照中存活的分身数恢复。地形与关卡规则在游玩中若保持不变，无需每轮复制。快照必须深拷贝，不能与当前棋盘共用可变数组或列表。历史只存在本次游玩的内存中，不写入关卡初始 JSON。

操作流程：

1. 移动：只更新玩家位置，不增加轮数、不向快照栈添加记录。
2. 空格：保存当前完整快照 → 基于当前状态同步计算下一轮 → 应用结果并增加轮数 → 检查通关。只有成功执行迭代才保留对应历史记录。
3. Z：若栈非空，弹出并恢复最后一份快照，刷新画面与轮数，依据恢复后的状态更新目标判定；栈为空时不改变状态。
4. R：从独立保存的关卡初始状态恢复布局与玩家位置，轮数归零，清空快照栈及运行中的通关状态。加载新关卡时也清空历史。

角色位置恢复规则（已确认）：Z 恢复到该次迭代按空格前的位置，同时丢弃该次迭代之后的移动。不能只回退普通细胞而保留当前位置，否则回退后的生命细胞可能与玩家重叠。

例子：第 0 轮玩家移到 A 后迭代，保存 `(第0轮布局, A, 0)`；第 1 轮移到 B 后迭代，保存 `(第1轮布局, B, 1)`；第 2 轮移到 C。按一次 Z 恢复第 1 轮布局与 B，再按 Z 恢复第 0 轮布局与 A。此时 R 才恢复关卡最初的玩家位置，Z 不单独撤销此前的移动。

撤销后可以重新移动、迭代，形成新路线；被弹出的未来状态不保留，首版无需重做功能。动画或结算过程中建议暂不接受移动、迭代、撤销与重置输入，确保一次状态变化完整结束。

#### 撤销历史容量（已确定暂定方案）

- 快照保存在本次游玩的内存中，退出关卡时释放；重置或加载新关卡时清空。
- **暂定最多保留最近 100 轮迭代的快照**。这是撤销容量，与关卡有效迭代上限分别管理；能否继续迭代由关卡上限决定。
- 容量满后，新增快照时移除最早的一份记录，始终保留最近的历史。撤销到历史边界时，Z 不再改变状态，界面提示「已到可撤销历史的起点」。
- R 始终可恢复关卡初始状态，不依赖最早快照是否仍在历史中；初始状态独立保存，不占用撤销容量。
- 上限作为统一配置项管理。当前采用小关卡设计，暂定保留最近 100 轮；后续根据实际试玩需要调整。
- 首版保存完整逻辑状态，不复制场景对象。内存占用随网格格子数和保留快照数增长；若有需要，可将细胞存活布局压缩为位数组。暂不实现磁盘历史或无限撤销。

验收例子：连续迭代 101 轮后，最多连续撤销 100 轮，恢复到完成第 1 轮迭代后的状态与第 2 轮迭代前的玩家位置；再按 Z 不改变状态，按 R 则恢复第 0 轮关卡初始状态。撤销后重新迭代时，记录新的迭代前快照并继续遵守容量上限。

### 2.6 主动分身

自动繁殖仍然移除。玩家可在自身周围八格中的有效空地创建分身，不覆盖已有细胞，不在墙或无效区域生成。每次创建一个，额度足够时可逐次填满八格。分身按普通生命细胞参与邻居计算、孤独死亡、拥挤死亡、数量与位置目标，并阻挡移动；它不是可操纵角色，每关仍只有一个玩家。

额度定义（已确认）：`cloneLimit` 是同时存活的分身数量上限，不是累计创建次数。迭代导致分身死亡时释放名额，可再次创建。初始普通生命细胞不占分身名额。分身创建不增加迭代轮数、不自动演化，仍由空格单独迭代。0 表示禁用分身，未填写时默认为 0；有效值为非负整数，按棋盘可用容量校验。

分身需要保留来源标记，即使演化行为与普通细胞相同，仍需区分初始普通细胞与玩家创建的分身，才能计算已用名额和限制回收对象。HUD 建议显示「分身 2/3」，表示当前存活数／上限，而非累计次数。

分身放置交互（已确认）：默认移动状态，使用固定 HUD 的「分身」按钮进入放置状态，高亮玩家本体周围合法空格，选择一格创建一个分身后返回移动状态。非法点击不创建且保持放置状态；取消按钮或 Esc 返回移动状态。进入放置状态时暂停移动与迭代输入，防止站位变化使候选格失效。切换模式的那次点击不能同时创建分身。

回收规则（全棋盘范围已确认）：玩家无需靠近，可回收棋盘任意位置上由自己创建的存活分身；初始普通细胞不可手动删除。回收立即释放一个分身名额，不推进迭代。交互建议为：通过回收按钮进入回收模式，点击一个分身移除后返回移动状态；满额时不自动删除最早分身，提示「分身已满，请回收一个」。

Z 维持按迭代撤销（用户当前偏好）：分身与回收不单独记录撤销步骤，迭代前快照仍须保存全部细胞来源标记及玩家位置。恢复快照时，同时恢复当时存活的分身，已用名额由存活分身数重新计算；不能只恢复细胞而保留当前额度。R 恢复初始关卡，移除游玩中创建的分身。显式全棋盘回收已确认，Z 仍按迭代回退，不改为按操作撤销。

注意：主动回收可以撤回摆放，但不能逆转刚才的一次回收。如果允许删掉任何分身又不提供对应撤销，玩家需要重新走到可创建的位置才能重建，这应在试玩中验证。允许回收的分身若放在目标格上，也不能成为永久存活的目标标记：仍会按死亡规则消失。

创建与回收结束后立即检查全部目标（已确认）。达到最后一轮后仍允许移动、分身与回收；尝试下一次迭代时提示失败，不执行超限迭代。主动分身是玩家的有限并发资源，替代先前「没有资源系统」的描述，不另加时间或敌人系统。

项目自定义程序集的允许引用方向：

```text
Gameplay ──→ Core ──→ Data
    └────────────────→ Data
```

- Core 可以引用 Data，不引用 Gameplay。
- Gameplay 可以引用 Core 和 Data。
- Data 不引用其他项目自定义程序集，避免循环引用；Unity 引擎类型仍可用于定义 ScriptableObject 等模板。
- Data 目录只放数据模板和类型定义，不放具体配置实例、表格内容或玩法逻辑。
- 具体配置资源与数据文件应放在 Data 代码目录之外；统一资源目录后续确定。

## 5. 关卡编辑器（优先开发）

### 5.1 场景与共享数据

关卡编辑器与游戏内容使用两个独立 Scene，建议命名为 `LevelEditor` 和 `Gameplay`。所有后续新增 Scene 统一放在 `Assets/Scenes`，编辑场景为 `Assets/Scenes/LevelEditor.unity`。这是运行在 Game 窗口中的编辑器，对应脚本放在 Runtime 下，不放入 Unity 专用的 Editor 目录。

编辑场景负责选择规则、设置网格、摆放和删除对象、配置通关条件、保存和加载关卡。游戏场景读取相同的关卡数据，执行规则并判定通关。关卡数据类型放在 Data，编辑操作与玩法执行分别由各自的 Runtime 模块负责；通用文件读写可以放在 Core。

以下内容按已确认需求编写，剩余建议均单独标注。JSON 以覆盖编辑器功能为准，可按实现需求调整。

### 5.2 选择生效的规则

- 正式机制已移除繁殖，不提供繁殖开关，也不保留可通过关卡参数重新启用的繁殖规则。
- 两个独立开关：孤独死亡（存活细胞少于两个邻居时死亡）、拥挤死亡（存活细胞大于三个邻居时死亡）。
- 关闭孤独死亡时少于两个邻居的存活细胞保留；关闭拥挤死亡时大于三个邻居的存活细胞保留。存活细胞有两个或三个邻居时始终存活，不设置存续开关；未触发已启用规则时保持原状态。
- 显示规则名称和简短说明。旧数据若包含繁殖规则，应报告不兼容，不能静默启用旧机制。
- 保存稳定的规则 ID，不使用显示名称或列表下标作为标识。
- 如规则需要参数，在选中后显示参数设置。首版仅使用已明确的两个死亡规则，阈值固定；不额外开发规则参数或规则变体。
- 加载到无法识别的规则时给出提示，阻止直接试玩，避免静默忽略规则。

### 5.3 网格尺寸与地形编辑

网格尺寸使用正整数 `width`（x）和 `height`（y），每个维度范围为 1～30，最大 30×30。建议数据坐标从左下角 `(0, 0)` 开始，x 向右、y 向上；菱形或旋转后的画面表现不改变逻辑坐标。四向移动已确定。x/y 定义棋盘的包围范围，不要求所有位置都有地块；边界不循环连接。

建议将每个位置划分为以下层：

| 层 | 类型 | 含义 |
| --- | --- | --- |
| 地形 | 无效区域 | 网格范围内没有有效地块的区域，不可行走 |
| 地形 | 有效网格（floor） | 可放置细胞和终点的地块 |
| 地形 | 墙面（wall） | 显式不可行走地块，可用于外围边界或内部障碍 |
| 对象 | 普通细胞（normal） | 放置在有效网格上的普通细胞 |
| 对象 | 玩家细胞（player） | 放置在有效网格上的玩家初始细胞 |
| 目标 | 终点 | 放置在有效网格上的目标标记，可与细胞重叠 |

策划图中的地形细胞对应编辑器中的固定墙面／不可行走地形，不是会演化的生命细胞。玩家不能进入墙面或缺失地块的无效区域。外轮廓可以通过删除地块形成不规则形状，内部也可以挖空；内部缺失地块同样不可行走，功能上相当于墙。显式墙面与无效区域是否需要不同美术表现可后续决定。

第二张图为关卡美术风格参考：浅色纸张纹理背景、柔和蓝紫色地块与细胞、带发光感的细胞中心、白色外缘与粉色中心的玩家形象，以及不规则棋盘轮廓。它展示视觉方向，不用于确定细胞状态或额外规则。红色标记、顶端图标、背景装饰和占位文字的含义均不据此推断。

逻辑保持二维方形网格，地块圆润或呈菱形的造型由表现层处理，不改变四向移动与八邻域计算。编辑器应清楚显示逻辑网格、地形类型和坐标；游戏场景可采用参考图的美术表现，但需要保证空格、固定地形、生命细胞与玩家易于辨认。

首版支持选择画笔后点击单格摆放，以及选择橡皮擦后点击删除。普通细胞和玩家细胞共用对象层，同格最多放置一个初始细胞；每关恰好一个玩家细胞（已确认）。编辑器建议再次放置玩家时将现有玩家移至新位置，而非增加第二个玩家。草稿允许暂时删除玩家，但试玩与正式加载校验要求恰好一个玩家。

删除对象或终点时保留地面。删除有效地块或改为墙面时，同时清除该格细胞与终点，避免留下无效引用。新建网格默认为全部有效地块，再删除不需要的区域。

改变网格尺寸以中心为基准，指调整逻辑格子范围，不是缩放地块尺寸。扩大保留原内容，新增位置按无效区域处理；缩小直接丢弃范围外的地形、细胞与目标，不弹出删除确认，不在后续扩大时恢复。若玩家被裁掉，草稿保留但标记缺少玩家，补放后才能试玩；目标被裁掉时同步移除目标坐标，目标列表为空则提示配置不完整。

奇偶尺寸变化可能使中心相差半格，无法完全居中且保持整数格坐标。采用确定的整数偏移约定：`offsetX = floor((newWidth - oldWidth) / 2)`，y 同理；旧位置加偏移后超出新范围的内容丢弃。例如 5→6 在右／上新增一列／行，6→5 从左／下裁掉一列／行。缩放后的所有地形、细胞及目标使用同一偏移。该偏置为实现约定，可在界面预览新范围。

### 5.4 通关条件与纸面例子

通关目标分为三类，与迭代上限分开配置：

| 目标 | 编辑器配置 | 纸面设计例子（非正式数值） |
| --- | --- | --- |
| 角色到达特定位置 | 目标坐标 | 角色到达 `(4,1)` |
| 生命细胞数量大于／小于指定值 | 比较符 `>` 或 `<`、数量阈值 | 普通生命细胞数量 `> 10`；或数量 `< 3` |
| 生命细胞覆盖目标位置 | 一个或多个目标坐标 | 同一结算状态下，普通生命细胞同时占据三个指定位置 |

数量比较采用严格大于／小于：例如数量等于 10 时不满足 `> 10`。角色对应玩家细胞；数量目标仅统计普通生命细胞，不包含玩家。当前位置目标按结算后的占据处理。所有目标在移动、分身、回收与迭代结算后统一检查；加载、撤销与重置后重新检查当前状态，编辑器提示初始即满足目标。移动不增加迭代轮数。

**迭代上限：** 轮数限制用于防止无限迭代，不是第四种通关目标，也不表示必须恰好第 x 轮达成。例如上限为 5 轮、目标为角色到达出口，则在允许的轮数内到出口即可通关；目标也可换成生命细胞位置或数量。建议保存为独立字段 `iterationLimit`。没有满足目标时，不因为轮数尚未超限而通关。

达到上限后允许继续移动、创建分身与回收，也可以因此达成目标。尝试下一次迭代时提示关卡失败，不执行迭代、不增加轮数、不添加快照。失败后允许 Z 或 R，不自动重置。

编辑器采用「添加目标 → 选择类型 → 设置参数」的列表形式，轮数上限单独设置。实际目标仅支持全部同时满足，轮数上限不参与目标组合。未设置迭代上限时默认为 1,000 轮，超限尝试按上述规则处理；撤销最多保留 100 轮，两者独立。

#### 普通生命细胞的多位置目标

普通生命细胞的位置目标支持多个坐标，像推箱子的多个目标格一样，要求所有目标位置在同一结算状态中被普通生命细胞覆盖。不要求是同一个细胞，也不记录之前曾经覆盖过的位置；玩家细胞占据目标格不算覆盖。

移除繁殖后，玩家可通过站位保护已有细胞或促使细胞死亡，也可主动创建分身覆盖初始为空的目标格。覆盖目标仍按完整结算结果检查，非目标位置有额外生命细胞不影响该目标，除非同时配置数量条件。

该目标目前保留在数据结构中，但关卡用途需要重新讨论：若所有目标初始已被覆盖，加载时就满足该目标；若有空目标，现在可通过主动分身覆盖，前提是玩家能靠近且额度足够。它可以单独用于分身覆盖目标，也可与数量或角色位置目标组合；不再沿用移除繁殖时「单独目标缺少过程」的结论。编辑器提示初始满足情况；不再仅因目标初始为空就判定不可达。

原先「下一轮自动繁殖覆盖三个空目标」的关卡方向已失效。主动分身可在玩家周围合法空格增加普通细胞，因此空目标是否可达需结合玩家路径与分身额度判断。

编辑器支持逐格添加和删除目标标记，显示已覆盖数量／总数，例如「2/3」。同一目标列表中坐标不得重复，所有目标必须位于有效地块。单个位置是列表长度为 1 的情况。

先用角色单终点举例，采用已确定的上下左右移动：

```text
y=2   .  .  .  .  .
y=1   P  .  #  .  G
y=0   .  .  .  .  .
      0  1  2  3  4  → x

P：玩家细胞；.：有效网格；#：墙；G：终点
```

目标：从 `(0,1)` 到 `(4,1)`。纸面路径示例：上 → 右 → 右 → 右 → 右 → 下，绕过 `(2,1)` 的墙，在终点结算后通关。

该图仅示范「角色到达特定位置」。角色停在邻格不满足条件；普通细胞占据该位置不满足角色条件，但可贡献普通生命细胞位置目标的覆盖；角色途中经过、最终离开时不满足占据条件。普通生命细胞的多位置目标采用全部同时覆盖；角色目标仍使用单个坐标。

### 5.5 JSON 保存方案（一关一文件，字段可按实现调整）

编辑器先仅供开发者在电脑上使用，采用**每关一个 JSON 文件**（已确认）。建议使用 UTF-8 编码，地形、细胞、目标分层保存。只记录关卡初始状态，不记录 GameObject、Prefab 引用、世界坐标或游玩过程。

建议使用带坐标的稀疏列表：`tiles` 只记录有效地面和显式墙面；范围内未记录的位置视为无效区域，范围外始终不可行走。这样容易表达参考图中的不规则轮廓。全矩阵也可行，但阅读与修改较大的不规则地图时更繁琐。

```json
{
  "schemaVersion": 1,
  "id": "level_001",
  "name": "终点测试",
  "grid": { "width": 3, "height": 2 },
  "rules": [],
  "iterationLimit": 5,
  "cloneLimit": 3,
  "tiles": [
    { "x": 0, "y": 0, "type": "floor" },
    { "x": 1, "y": 0, "type": "floor" },
    { "x": 2, "y": 0, "type": "floor" },
    { "x": 0, "y": 1, "type": "wall" },
    { "x": 1, "y": 1, "type": "floor" }
  ],
  "cells": [
    { "x": 0, "y": 0, "type": "player" },
    { "x": 1, "y": 1, "type": "normal" }
  ],
  "winConditions": {
    "combine": "all",
    "conditions": [
      { "type": "actorAtPosition", "position": { "x": 2, "y": 0 } }
    ]
  }
}
```

该例只展示数据格式；实际文件列出所启用的死亡规则。阶段 1 已实现稳定规则 ID `lonelyDeath`（孤独死亡）、`crowdedDeath`（拥挤死亡），条目采用 `{ "id": "lonelyDeath" }`。阈值固定，当前不支持自定义参数；兼容空 `parameters: {}`。空列表表示两种死亡规则均关闭，允许保存及试玩，但提示迭代不会改变细胞。`schemaVersion` 当前为 1；未知版本报错。具体代码入口与验证结果见 [实现状态](/Users/aoi/UnityProjects/taptap2026-emergence/Docs/ImplementationStatus.md)。

其他两类目标的建议 JSON 条目如下，分别展示格式，不表示应同时添加到同一关卡：

```json
[
  { "type": "livingCellCount", "operator": ">", "value": 10 },
  {
    "type": "livingCellsCoverPositions",
    "positions": [
      { "x": 2, "y": 3 },
      { "x": 3, "y": 3 },
      { "x": 4, "y": 3 }
    ]
  }
]
```

目标标记由坐标条件生成，避免同时保存一份终点坐标和一份条件坐标而产生不一致。当前方案不保存运行时迭代次数或条件达成状态。

保存位置建议区分用途：

- 制作中的关卡：默认保存到项目的 `Assets/StreamingAssets/Levels`，一关一文件，建议文件名使用稳定关卡 ID，例如 `level_001.json`。开发者桌面编辑器使用该目录读写；覆盖保存同一关卡，另存为使用新 ID。
- 随游戏发布的关卡：可放入 `Assets/StreamingAssets/Levels`，作为只读初始内容；读取方式需按最终平台实现。
- 运行时用户创建的关卡：可保存到 `Application.persistentDataPath/Levels`；若目标是 Web，则另行设计导入、导出与持久化流程。

关卡文件独立于现有 Excel → `database.json` 流程，不把手工编辑的关卡合并进全局表文件。

### 5.6 首版验收

- 能选择规则、设置 x/y 尺寸，逐格摆放和删除地块、墙、普通细胞、玩家细胞及终点。
- 保存再加载后，尺寸、规则、地形、初始细胞与目标保持一致。

### 5.7 编辑器试玩方案（已确认）

保留 LevelEditor 与 Gameplay 两个 Scene，但 LevelEditor 支持在当前场景内切换「编辑／试玩」模式。两个场景共用同一套棋盘构建、移动、迭代、目标判定与撤销逻辑；各自负责不同的 UI 和流程，不维护两套规则实现。

点击试玩前校验草稿，将当前草稿深拷贝为试玩初始数据，无需先保存 JSON。2026-10-17 已接入左下“试玩当前草稿”和 HUD“结束试玩 · 返回编辑”，编辑／试玩保持同一 Scene；实际新版 Play Mode 验收见实现状态。试玩时禁止编辑画笔操作，开启游戏输入、迭代计数与撤销。R 恢复这次试玩开始时的数据；结束试玩则丢弃游玩状态和历史，恢复原草稿及编辑视图，不把演化结果写回草稿。

编辑器内试玩先验证棋盘规则与目标；Gameplay 用于验证正式胜利界面、叙事对话与关卡切换等完整流程。正式流程测试可另外提供进入 Gameplay 的入口。

手势分工建议（待确认）：单指滑动移动角色；双指捏合缩放、双指同向拖动平移棋盘，不采用长按单指平移。棋盘手势不从 HUD 区域开始；一旦出现第二根手指，取消本次单指移动候选，直到所有手指抬起才接受新移动。建议单指移动在抬起时判定，以避免双指操作开始前先误走一格。设置最小滑动距离与方向判定，短点击不移动，模糊斜向滑动不触发。若后续坚持长按平移，应等待抬起才执行移动，长按进入平移后取消移动判定。

棋盘在扣除 UI 与安全区域后的可用空间内等比例显示，适配宽屏、窗口变化和手机安全区域。最大 30×30 棋盘允许后续用缩放查看细节；限制缩放范围与平移范围，并提供回到全图的入口。完整手势、触控尺寸与真机验证留到 Android 版本实施。

PC 与 WebGL 优先开发和验证；当前预留触屏输入与布局适配的扩展空间，Android 的完整适配、打包与真机验证放到后续有时间时进行。

通关后显示关卡胜利界面，可能插入叙事对话；标题与人体选关主流程已明确，见第 9 章；结算表现、对话流程、关卡解锁与进度保存细节后续讨论。

## 8. 世界观与叙事

### 8.1 世界背景（用户设定）

故事发生在架空世界。人类即将灭亡之际，一个组织研发出人工编程生命「织群」（暂名）：类似机器人、以细胞自动机为基础的生命载体，能够承载移植的人类意识。织群之外还存在其他人工编程生命分支，主角的身体来自其中一个分支。

组织发现「A」结构能够自行演化并形成更高级的生命体。一部分人企图将其用于自身目的，具体用途尚未决定，候选方向包括治疗、武器与细胞修复。A 最终失控，形成新的自我意识，并侵入织群乃至人类身体，逐步掌控世界。A 目前被称为病毒，其感染、控制与记忆干预机制尚待定义。

人类原本为何濒临灭亡尚未确定；不能直接将其归因于后来失控的 A。

### 8.2 主角身份与记忆（用户设定，含剧透）

主角是另一人工编程生命分支创造的生命体，意识来自一个已经死去的人。一次实验事故使其失忆。主角为找回记忆、摆脱 A 的控制而寻找真相。

主角起初试图控制病毒扩散，发现此路不通后，转而诱导变异。随着关卡推进，主角发现人为创造的生命结构，并逐渐恢复混合的记忆：既有原意识生前的记忆，也有不属于他的记忆。

这些片段使主角误以为自己就是研制 A、企图操控世界的凶手。实际是凶手的记忆与主角自身记忆混合，误认身份属于 A 的计划。意识移植、实验事故、A 干预的先后关系，以及原意识死亡的原因尚待明确。

### 8.3 暂定事件线

用户提供的时间线参考图包含：人工病毒研究 → 无法解释的群体演化 → 实验设施事故 → 感染爆发与世界崩塌 → 0159-666 项目启动（代号随手拟定）→ 主角作为项目成员执行特殊实验 → 发现异常结构 → 怀疑病毒经过人工设计 → 心理压力下决定主动促进演化 → 实验成功并获得关键数据 → 揭晓真相。

该图作为初步顺序参考。图中「主角为项目成员」究竟指其生前身份、移植后的经历，还是被误认的凶手记忆，暂不定论。需要区分真实历史、主角经历和错误记忆，避免将误导线索写成真实历史。

### 8.4 叙事与玩法连接（建议，未确认）

| 阶段 | 主角的理解 | 关卡与叙事的连接方向 |
| --- | --- | --- |
| 遏制 | 先阻止扩散 | 使用细胞数量目标，让玩家学习通过站位保护细胞或促使细胞死亡；完成局部目标不等于解决世界危机 |
| 诱导 | 单纯减少数量无法摆脱 A，需要研究变化 | 以迭代轮数和位置目标引导实验，观察结构在不同干预下的变化 |
| 误认 | 反复出现的结构和记忆使主角怀疑自己是创造者 | 复现人工结构时出现记忆片段；为身份误导同时安排可核对的矛盾线索 |
| 真相 | 主角意识与凶手记忆并非同一来源 | 用独立记录与记忆中的视角矛盾支持揭示，而不只靠结尾解释 |
| 终局 | 决定是否完成 A 所需要的演化 | 最后的干预与迭代产生不同结构，对应不同结局 |

「精确结构匹配」尚不在现有通关条件中。如果后续需要玩家构造完整图案，必须明确新增条件；早期可先通过现有的位置、数量与迭代条件验证叙事关卡，不默认它们足以识别特定结构。

### 8.5 A 操纵主角的动机（建议，未确认）

建议设定：A 能复制既有模式并传播，却无法独自完成某种需要外部干预的结构转换。主角的特别细胞能改变邻域计数、不因死亡规则消失，成为完成该转换的关键。A 混入创造者记忆，使主角相信自己有责任修复灾难，诱导其主动推动演化。

需要解释 A 为什么不能制造或操控等效干预者，以及主角为何仍有自主性。「需要外部干预」作为世界设定，不能仅凭细胞自动机规则推导。最终压制 A 的结构也需要提前铺垫其作用范围与代价，不采用无前置依据的万能解药。

### 8.6 结局方向

**结局一：推演与涌现（用户方向，具体机制待定）。** 主角推演出 A 的最终结构，记忆与结构涌现，制造出能够压制 A 的事物。其形式、压制机制、影响范围和代价未定。

建议将其具体化为「限制 A 演化的稳定结构」：不消灭所有人工生命，而是在有明确作用机制的范围内阻止 A 继续复制或接管意识。结构是否传播、是否需要主角持续干预、是否会限制织群能力，均需进一步设计。

**结局二候选 A：完成者（怪结局，建议）。** 主角接受混合记忆中的自责，相信完成最终结构就能修复世界，实际完成了 A 所需的转换。感染表征消失，细胞呈现有序状态，但原本独立的意识被统一；主角最后听到自己的记忆由其他生命同时说出。此结局需要预先提示「有序／稳定不等于恢复自主意识」。

**结局二候选 B：隔离（普通结局，建议）。** 主角不再推进危险实验，切断实验区域与外界的连接，保存当地幸存意识。A 仍存在于外界，主角暂时自由，身份真相未完全解开。隔离设施与能力必须在故事中提前建立，不能临时出现。

结局分歧建议来自最终关卡的干预与结构结果，并在不可逆行动前给出可理解的线索。撤销与重置属于玩家操作功能，目前不设为故事中的时间倒流能力。

### 8.7 移除繁殖后的叙事衔接（待讨论）

游戏棋盘中的普通生命细胞不再自动繁殖，新增细胞来自玩家主动分身。世界背景中 A 的复制、感染与高级结构涌现仍保留为叙事设定，不据此重新引入棋盘繁殖。关卡中的结构变化改为通过选择性存活与死亡形成剩余结构；原先依赖新生细胞的叙事关卡与终局推演需重新验证，尚不自动改写世界历史。
