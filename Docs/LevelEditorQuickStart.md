# 关卡编辑器：配置与同场景试玩

2026-10-17：用户已确认 JSON 保存可用，`002.json` 为用户新建的关卡；加载重开及其他手动验收仍按文末清单确认。所有新增 Scene 统一使用 `Assets/Scenes`。

## 启动

1. 打开 Unity 2022.3.62f3 项目，等待脚本导入编译。没有新菜单时执行 Assets → Refresh，检查 Console 是否有编译错误。
2. 执行 **Tools → Levels → Run Editor Checks**。预期 Console 输出 `Level editor checks passed: 33`。
3. 执行 **Tools → Levels → Create Level Editor Scene**。若当前场景有未保存改动，按 Unity 提示保存；取消则不创建新场景。
4. 新场景保存为 `Assets/Scenes/LevelEditor.unity`，随后点击 Play。棋盘、工具栏及 EventSystem 在运行时构建，非 Play 状态仅有引导组件与背景相机。
5. 场景已存在时无需重建，打开已有 Scene，退出旧 Play 后重新点击 Play 即可加载新版界面。旧版本运行中的内存草稿不会自动迁移，不要把退出 Play 当作保存。

## 操作

- 初始为 10×10 有效地面，坐标左下为 `(0,0)`。
- 左侧选择画笔，点击右侧单格。不支持拖动连续绘制，点击工具栏不会同时修改棋盘。
- 有效地块／墙面：编辑地形；删除地块产生不可行走的缺口。墙面或缺口不允许放细胞、目标。
- 普通细胞显示 C，玩家显示 P。再次放玩家会移动已有玩家；不能直接覆盖普通细胞，先用擦除细胞清空。
- 角色终点显示 G，再次放置会移动这个目标；细胞目标显示 T，可添加多个，不重复添加。
- 擦除细胞保留地面与目标；擦除目标保留地面与细胞；墙面或删除地块会清掉该格细胞及目标。
- 输入 X／Y（1～30）后点击居中调整尺寸。范围外内容直接丢弃，新增范围无地块；删除的内容在再次扩大时不会恢复。
- 奇偶变化使用 GDD 约定：5→6 在右／上增加范围；6→5 从左／下裁切。玩家与目标和地形一起偏移。
- 新建空白关卡清除当前内存草稿，按输入尺寸填满有效地块。

## 保存、另存为与加载

1. 顶部填写关卡 ID（例如 `level_002`）与显示名称。ID 使用英文字母、数字、下划线或连字符，首位为字母或数字；名称可以用中文。
2. 点击 **保存**，文件立即写入 `Assets/StreamingAssets/Levels/<ID>.json`，底部显示完整路径，顶部显示已保存。
3. 已加载／保存的关卡再次点击保存，会覆盖同一 ID；想复制为另一关，修改 ID 后点 **另存为**，原文件保留。另存为拒绝覆盖已有 ID。
4. 初次保存若目标 ID 已存在，会先询问是否覆盖。没有保存的改动在新建／加载前也会提示是否放弃。
5. 已有文件下拉列表选中文件后自动加载，无需额外按钮。有未保存编辑时仍先确认；取消后回到默认选项。外部新放入的 JSON 可用刷新列表更新。文件损坏、删除或无法读取时保留当前草稿，自动刷新列表并选中“请选择已保存的关卡”。
6. 保存允许缺少玩家、未完成目标等不完整草稿，但不能使用非法 ID 或未应用的非法数字。网格尺寸改变要先点居中调整，保存不会偷偷裁切。

退出 Play 后只会丢失未保存的编辑；已经写入磁盘的 JSON 可以下次加载。现可直接点击左下“试玩当前草稿”，无需先保存或切换 Scene；结束试玩返回原编辑数据。参见 [玩法测试说明](/Users/aoi/UnityProjects/taptap2026-emergence/Docs/LevelPlayQuickStart.md)。

## 规则、额度与通关目标

右侧配置栏支持滚动：

- 勾选孤独死亡／拥挤死亡，输入同时存活分身上限和迭代上限，然后点应用规则与上限。分身留空为 0，迭代留空为 1000；两种规则可都关闭。
- 添加角色位置、细胞覆盖或数量条件，在下拉列表选择当前编辑的目标。所有条件同时满足。
- 角色位置／细胞覆盖：点在棋盘设置，然后点击有效地块。细胞覆盖可有多个位置；移除目标格只擦当前目标，清空本目标坐标保留条件但清掉坐标。
- 数量条件：选择 `>`／`<`，输入阈值并点应用数量条件。留空可保存未完成草稿。删除本目标会移除整个条件。
- 顶部保存会一并应用当前规则、额度和数量输入；无效数字会阻止保存并提示原因。
- 点击校验关卡，在弹窗中查看全部错误与提示。缺少玩家、空目标和不合法目标坐标会报错；初始即满足全部目标、两个死亡规则都关闭是提示。

**点击擦除全部目标会清掉该格涉及的所有位置目标；擦除本目标只处理右侧选中条件。**

## 手动验收

1. 在棋盘中心放玩家，再在另一空地放玩家，确认只留下一个 P。
2. 放普通细胞和目标，然后用墙或删除地块覆盖，确认内容被清除；擦除细胞则应保留目标。
3. 新建 6×6，在 `(0,0)` 放玩家，在 `(1,1)` 放普通细胞与细胞目标；缩到 4×4，确认玩家消失，普通细胞与目标移至 `(0,0)`。再放大，确认旧玩家没有恢复。
4. 调为 30×30，确认棋盘仍完整可见并可准确点击四角；改变 Game 视图宽高比，确认没有格子被裁切。
5. 输入 0／31 等非法尺寸，确认状态栏提示错误且草稿不变。
6. 点击工具栏、输入框及按钮，确认不触发背后棋盘的画笔。

7. 保存一份完整关卡，退出 Play 后重新进入，从文件列表加载，确认地形、细胞、目标、规则与额度一致。
8. 更换 ID 另存为后再加载原关，确认原关未改变；试图另存为已有 ID 应提示错误。
9. 添加两个细胞覆盖目标，分别选中后点不同的格子；移除本目标格不得影响另一目标。
10. 点击校验关卡，检查空草稿错误、初始满足提示、两个规则关闭提示。弹窗阻止对背后棋盘误编辑。

配置服务检查菜单：**Tools → Levels → Run Configuration Checks**，预期输出 `Level configuration checks passed: 34`。

独立编译与逻辑验证：`bash Docs/Tests/run-level-data-checks.sh`（47 项数据检查、33 项编辑检查、34 项配置检查、63 项玩法检查、44 项历史／输入检查、15 项试玩／关卡检查）；`python3 Docs/Tests/check-level-editor-compilation.py`（UI 与场景工具实际程序集编译，不替代 Play Mode 验收）。


## 同场景试玩（阶段 6）

- 在当前 LevelEditor 场景 Play，设置玩家、完整目标和合法参数，然后点击左下 **试玩当前草稿**。可以从文件列表加载 `stage6_probe` 作为验证关。
- 试玩会先应用规则／数量输入，尺寸输入需先明确应用；无需保存 JSON。非法草稿继续留在编辑界面并列出错误。
- 编辑面板隐藏，原草稿、画笔、目标选择和滚动位置保留。试玩以独立副本运行，方向键／Space／Z／R 与按钮共用原玩法。
- 点击 HUD 的 **结束试玩 · 返回编辑**，可以从选择、暂停或胜败状态返回；试玩对象、状态和历史丢弃，不覆盖草稿或正式进度。
- 试玩和 Gameplay 共用 Organic 细胞视图，编辑态仍为清晰的方格／字母标记。Shader 与动画的实际视觉验收待执行。
